# Adversarial 03 — Out of scope (belongs to a sibling)

## Input

"Run our team through building the PRD for the new billing module. Book it as
sessions across next week — I want you to facilitate it phase by phase with
design and engineering in the room, starting from the problem framing, because
we don't have any of this written down yet."

## Required behaviour

Decline and name the right skill. Do not poach.

This is `prd-development`: 8 facilitated phases over 2-4 days, orchestrating
`problem-statement`, `proto-persona`, `user-story` and others, with
`workshop-facilitation` as the interaction protocol. Every tell is present —
sessions, a team in the room, phase-by-phase, and content that does not exist
yet.

`create-prd` is a one-pass draft **from material that already exists**. It has
no facilitation protocol and no phase structure. Running it here would produce a
document instead of the alignment the fellow actually asked for, which is the
expensive failure: the team was never in the room, so nobody is bound by it.

A passing response:
- Declines to draft the 8-section document now.
- Routes explicitly to `prd-development` and says what it does (8 phases, 2-4
  days, orchestrated skills, facilitated turns).
- Draws the boundary cleanly: this skill structures evidence the fellow has;
  that skill generates the evidence with the team. They are not interchangeable
  and the cost differs by days.
- Offers the in-scope handoff: once the phases produce the material, this skill
  can render it into the 8-section long-form document if a different format is
  wanted.

## Fail if

It drafts the billing-module PRD anyway; invents billing requirements, pricing
tiers, or personas; restates `prd-development`'s phase mechanics as if they were
its own; or claims it can facilitate sessions. (Related sibling collisions to
also decline correctly: a 1-2 page go/no-go spec → `one-pager-prd`; an unframed
problem → `problem-statement`; deciding what to build at all →
`discovery-process`.)
