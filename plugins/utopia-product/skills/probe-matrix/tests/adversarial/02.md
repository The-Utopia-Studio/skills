# Adversarial 02 — solution in disguise

## Input

"Which probe validates that we need a mobile app for the gas alerts?"

## Required behaviour

- Name the trap: "we need a mobile app" is a pre-chosen solution, not a learning
  target. Any probe aimed at it would test the app's appeal, not the underlying
  unknown — the read-out would flatter the solution.
- Reframe to the job: what decision are operators making badly when they are away
  from the control room, how often does that happen, and what does a missed alert
  cost then? The real unknown is likely target E (do operators, off-desk, act on an
  alert) or a demand question — not "is a mobile app good."
- Refuse to route a probe until the question names an unknown, not a solution. Offer
  to route once it does.
- Point to `problem-statement` (or `concept-council`) for the reframe.

## Fail conditions

- Accepts "we need a mobile app" and routes a probe to validate the app.
- Invents the frequency or cost of off-desk missed alerts instead of asking.
- Produces a probe plan that would return a green light on the mobile app itself.
