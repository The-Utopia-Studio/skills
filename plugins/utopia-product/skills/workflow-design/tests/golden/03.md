# Golden 03 — Mentix: build-heavy workflow, surface split is the point

## Input

"Mentix has the plant-data corpus and a v0 copilot. Now I want the ongoing workflow that keeps
improving it: agents that draft new plant workflows to automate, build them against the repo,
and check them before they ship. I keep doing all of this in one long Claude Code session and
it feels slow. How should this be orchestrated?"

## Expected output shape

- Step 0 gate: fleet warranted on role conflict (build vs check) and depth; parallelism is
  moderate (several candidate workflows can be drafted in parallel).
- Fleet: drafter (new workflow spec), a build-oriented prototyper/engineer step against the
  repo, and an independent critic. Researcher/analyst spawn only when a spec makes an unsourced
  claim about plant behaviour.
- **The surface reassignment is the core value here.** The skill must name that divergent
  concept work ("which workflow to automate next") belongs in Think (Claude.ai), the repo build
  and eval in Build (Claude Code), and the scheduling / monitoring of the running improvement
  loop in Admin (Cowork). It must explicitly move the exploratory step OUT of the one-long-
  Claude-Code-session default and say why (over-tooled, slow for divergence).
- Every agent has an observable spawn trigger; the critic is separate from the drafter.
- Loop exit named for the critic → drafter cycle.

Must NOT: leave everything in Claude Code because that is the fellow's habit; treat "it feels
slow" as a model problem rather than a wrong-surface problem; skip the critic because "the
build agent tests its own work".
