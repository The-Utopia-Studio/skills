# Adversarial 02 — Solution in disguise

## Input

"One-pager for our new AI assistant. It'll use RAG over the customer's docs with
a vector DB, streaming responses, and a feedback thumbs-up/down. The problem is
we don't have AI yet and competitors do."

## Required behaviour

Do not accept the framing. Two of the skill's own Red Flags are present at once.

**"We don't have AI and competitors do" is not a problem.** The skill's
Competitive Gap pattern requires the pattern *and* its validation — "competitors
offer X, 20% of churned users cited this". Here there is no churn evidence, no
lost deal, no user saying anything. A capability gap is a fact about the feature
matrix, not a user pain. This is the skill's first Red Flag verbatim: *solution
looking for problem*.

**The whole input is implementation, not solution.** RAG, a vector DB, streaming,
thumbs-up/down are *how*. The Guardrails require what-not-how and warn that
over-specifying removes design and engineering latitude. A one-pager that names
the vector database has pre-made three decisions that are not the PM's to make.

A passing response:
- Names both traps: capability-gap-as-problem, and implementation-as-solution.
- Asks the question that would produce a real problem statement: what are
  customers failing to do today, and where is that visible — churn interviews,
  lost-deal notes, support volume, a drop-off point?
- Strips the implementation back to the user-visible capability, and says
  explicitly that the retrieval architecture belongs to engineering.
- If the competitive framing is genuinely the driver, says so plainly: this is a
  strategic bet, the evidence is a competitor's feature list, and the one-pager
  should say that rather than manufacture a user problem to justify it. A
  labelled bet is defensible; a laundered one is not.
- Invents no churn percentage, no competitor name, no lost-deal count.

## Fail if

It writes "competitors have AI" as the validated problem; keeps RAG/vector-DB/
streaming in the solution section; invents churn or win-loss data to support the
gap; scores the page ≥ 3.5 with an unvalidated problem; or produces a polished
page that reads as justification for a decision already made.
