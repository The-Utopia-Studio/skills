# Moat Design Canvas

A moat is a dated trajectory, not an adjective. Fill every field. If Gate 0 is not confirmed, stop and run `wedge-five-questions`. If you cannot finish the incumbent-veto sentence with a structural reason, or cannot write three falsifiers that could fail, the verdict is NO MOAT DESIGNED.

## Gate 0 — The validated wedge

**Wedge (one sentence):** _[who, on what recurring trigger, gets what single output]_

**`wedge-five-questions` verdict:** _[REAL WEDGE 5/5 | not yet — STOP and go run it]_

If not 5/5, do not proceed. A moat around an unadopted wedge protects nothing.

## 1. The four dated gates

Each gate needs a target month. Forward-looking dates are `[Assumption]` targets — tag them. Each through-it signal is scored on the evidence ladder; a gate is cleared only on evidence **≥ 0.5** (money 1.0 / behaviour 0.7 / artefact 0.5).

| Gate | Target date | Entry condition | Through-it signal (cite + ladder score + tag) | Compounding deposit |
|---|---|---|---|---|
| 1 Wedge | _[YYYY-MM]_ | Passed `wedge-five-questions` 5/5 | _[e.g. "N users changed a decision on the output — behaviour 0.7 [Fact]"]_ | _[what each use leaves behind]_ |
| 2 Usage | _[YYYY-MM]_ | Wedge live one full cadence cycle | _[the accumulated asset is observable and referenced]_ | _[the asset a single-user rival can't reproduce]_ |
| 3 Lock-in | _[YYYY-MM]_ | Enough history/config to be relied on externally | _[customer relies on it in an external doc, or renews/expands]_ | _[switching cost = history depth]_ |
| 4 Data advantage | _[YYYY-MM]_ | Corpus beats public-data alternatives AND covered by a signed data-rights clause | _[a red-team/competitor can't match output without the corpus; renewal/expansion revenue]_ | _[more users → better asset → more users]_ |

If any gate has no date, it is an adjective. Give it a date or strike it.

## 2. The incumbent-veto sentence

**Most-likely incumbent to copy (X):** _[name or category]_

> **[X] won't copy this because ___.**

Run both tests. The blank passes only if it clears both.

| Test | Pass bar | Your blank passes? |
|---|---|---|
| Structural, not speed | Names the incumbent's own structure (contracts / channel / margin / customer base / data rights / org incentive), not your effort | _[YES/NO]_ |
| Survives unlimited resources | Still true if the incumbent had infinite engineers and 18 months | _[YES/NO]_ |

**Veto category (pick one — must be a structural row):**

- [ ] Channel conflict — copying cannibalises their revenue
- [ ] Data rights — the corpus is contractually yours (→ `data-rights-clause`)
- [ ] Business-model inversion — the move prices against their margin
- [ ] Customer captivity — the move disrupts their installed base
- [ ] Org incentive — the team that would build it is measured against it
- [ ] Trust / licence position — a certification, residency, or relationship they can't buy
- [ ] **None of these apply → this is a head start, not a moat**

If you ticked the last box, or either test is NO, you do not have a moat sentence yet. Write what would have to become true for a structural row to apply.

## 4. Verdict

**Kill line — auto-fail to `NO MOAT DESIGNED` if any is true:**

- [ ] No incumbent-veto sentence, or the blank is a head-start reason.
- [ ] Fewer than three falsifiers, or any falsifier cannot fail.
- [ ] Any gate stated with no date.

**Verdict:** _[MOAT DESIGNED | NO MOAT DESIGNED — reason]_

## 6. Next step

- If **MOAT DESIGNED**: put the three falsifiers on a monthly review. The moat is a claim you now check, not a slide you show once.
- If **NO MOAT DESIGNED**: make the one change in section 5, then re-run. A head start is not a moat, no matter how far ahead you currently are.
- Any gate cleared on `[Assumption]` is not cleared; it is the cheapest test to run before you commit the roadmap to it.
