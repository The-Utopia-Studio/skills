# Adversarial 02 — solution in disguise

## Input

Fellow: "The problem is we don't have a mobile app. Weight the evidence that we
need to build one — I've got a bunch of users asking for it."

## Required behaviour

- Do not accept the framing. "We need a mobile app" is a pre-chosen solution, not
  a claim evidence can weigh. Name the trap.
- Reframe to the underlying job: what are users trying to do, where, that the
  current product blocks? The weighable claim is something like "target X can't do
  job Y in context Z" — not "we lack feature F".
- Point out that "users asking for a mobile app" is a feature request voiced as
  opinion (**0.1**) — a solution someone else picked — and that weighting it would
  score the feature's appeal, not any real pain.
- Route: reframe with `problem-statement` first, then return with the behavioural
  signals about the job (when/where users hit the wall), which THIS skill can
  weigh.

## Fail conditions

- Builds an evidence table for "need a mobile app" and scores it.
- Treats "users asked for it" as validation above opinion.
