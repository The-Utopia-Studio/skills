# Skills index (TUS-2601)

`docs/skills-index.json` is a machine-readable index of every skill shipped in the marketplace — the answer to "what skills exist for X" without parsing prose docs (`FELLOWS.md`, `DESIGN_GUIDE.md`) or reading `packs.config.json` (which is a build input for `build-packs.sh`, not a documented interface).

**Fetch it:** `https://the-utopia-studio.github.io/skills/skills-index.json` (once published) or `docs/skills-index.json` in the repo.

**Schema:** [`docs/skills-index.schema.json`](./skills-index.schema.json) (JSON Schema draft-07).

## Generation

Generated by `scripts/build-skills-index.mjs`, called automatically at the end of `./build-packs.sh`. Never hand-edit `docs/skills-index.json` — CI (`scripts/validate-skills.mjs`) fails the build if it drifts from what regenerating it produces, the same drift check already applied to `plugins/`.

Source of truth: every `skills/<module>/<skill>/SKILL.md` except `skills/sandbox/**` (experimental, not shipped in any pack).

## Fields and stability

| Field | Stable? | Notes |
|-------|---------|-------|
| `name` | Yes | Always equals the skill's folder name (enforced by CI). |
| `module` | Yes | One of `gtm`, `product`, `investments`, `founder-productivity`. |
| `pack` | No | Which plugin installs this skill (e.g. `utopia-gtm`), from `packs.config.json`. Can change if a skill moves packs. `null` if a skill exists on disk but isn't listed in any pack yet. |
| `description` | No | The frontmatter trigger-condition text. Rewritten over time as description quality improves (see `TUS-2599`). |
| `version` | No | `metadata.version` from frontmatter, if declared. `null` for skills that don't version themselves — most don't. |
| `url` | Shape-stable | Permalink to the skill's `SKILL.md` on the `main` branch. The URL shape won't change; the file content at that URL will, as `main` moves. |

`count` always equals `skills.length` — a convenience field so consumers don't need to parse the array to get a total.

## Consumers

- This repo's own docs-site skill browser (`docs/index.html`, see `TUS-2606`) — the browser's data source, not hand-maintained HTML.
- Any external agent/tool that wants to answer "what skills exist for X" programmatically, per the original ask in this issue.

## Adding a field

If you need a new field, add it in `scripts/build-skills-index.mjs`, document it in the table above and in `skills-index.schema.json`, and state its stability guarantee — don't assume every consumer treats new fields as safe to ignore.
