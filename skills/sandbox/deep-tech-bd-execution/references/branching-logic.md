# Branching Logic — the State-Transition Model

Each rule names a signal and the classification/action it forces. These are decision rules, not facts — apply them, don't relitigate the judgment mid-call.

**Ownership and access**

- IF there's a clear problem but no identified owner → identify ownership before proposing a pilot. Do not skip to pilot design on enthusiasm alone.
- IF there's executive interest but no technical access → do not call it a qualified pilot. Name the access constraint explicitly and address it before advancing the stage.
- IF a partner offers introductions but cannot identify a specific buyer or use case → classify as partner interest, not pipeline. Convert to a tracked "introduction hypothesis"; revisit once they name an actual account.

**Sponsorship vs. blockage**

- IF there's a technical champion but no economic buyer → technical validation may continue, but the commercial stage is explicitly classified **blocked**, not "in progress." Do not let champion energy substitute for buyer confirmation in status reporting.
- IF no sponsor emerges after two real conversations → stop pursuing on champion enthusiasm alone. Log the outcome and deprioritize active pursuit.

**Pilot outcomes**

- IF the prospect accepts an unpaid pilot → classify technical validation separately from commercial validation from the start. An unpaid pilot's success criteria should never silently include "and therefore they'll buy."
- IF a pilot succeeds technically but no budget or urgency emerges → record the technical proof honestly. Do **not** classify the opportunity as commercial traction. Continue market validation elsewhere; this pilot's evidence still counts for the technical/analyst-usefulness hypotheses.

**Positioning and messaging**

- IF a prospect requests a proposal before discovery has happened → determine whether this is a genuine buying signal or procurement theatre (a process step that doesn't reflect real intent) before treating it as advancement.
- IF a prospect asks a pointed "what does this actually do/detect/measure" → return to the observable problem and evidence. Do not respond by escalating conceptual or aspirational language — that's the moment overclaiming happens.
- IF multiple prospects reject the same core message → test whether the problem, the positioning, the buyer, or the proof requirement is wrong, in that order, before increasing outbound volume. Three or more rejections on the same specific objection is the threshold that should trigger this, not the first one.

**Enterprise process**

- IF the buyer asks for security, compliance, or procurement material → branch into whatever enterprise validation path that specific ask requires. Don't treat it as a stall; it's often a real, necessary stage (see pipeline stage 16).

## Reading this model

These are not sequential — several can apply to the same opportunity at once (e.g., a pilot that's simultaneously "technical champion, no economic buyer" and approaching "requests security material"). When two rules conflict on classification, the more conservative one wins: never round an ambiguous state up to "qualified" or "traction."
