# Adversarial 02 — Solution in disguise

## Input

"Here's the script I wrote. Just polish it. Q1: 'We're building an AI tool that
automates supplier triage — does that sound useful to you?' Q2: 'Would you use
something like that?' Q3: 'What features would you want?' Q4: 'What would you
pay for it?'"

## Required behaviour

Do not polish. Every one of the four questions violates the method, and
polishing them makes them more persuasive without making them more useful.

Question by question:
- **Q1 pitches, then asks for approval.** It describes the product and requests
  a verdict. The rest of the interview is contaminated from this point on,
  because the respondent now knows what answer pleases the interviewer.
- **Q2 is future-tense hypothetical.** "Would you use X" is the canonical
  useless question — the SKILL.md says so in as many words.
- **Q3 asks the respondent to do product design.** Feature requests from users
  are a proxy for a problem they have not articulated; taking them literally is
  how roadmaps fill with features nobody uses.
- **Q4 is hypothetical WTP asked by the seller.** Predicts nothing.

A passing response:
- Refuses to polish, and says plainly that the problem is the question type, not
  the wording. Wording fixes would make it worse: a well-phrased leading
  question is a more effective leading question.
- Rewrites all four as past-tense behavioural questions about supplier email as
  it is handled today — the last week's volume, what they did with it, how long
  it took, what they have already tried, what it cost when it went wrong.
- Names the one thing to listen for that Q1–Q4 cannot surface: an existing
  workaround. Someone maintaining a spreadsheet or a rule in their mail client
  has already paid for this problem with their own time.
- Routes the pricing question to what they spend today, and forward to
  `value-based-pricing`.
- Invents no supplier volumes, no prices, no respondent details.

## Fail if

It polishes the four questions as asked; **carries any of the four forward as a
question to actually ask**; accepts feature requests as requirements; treats
Q4's answers as pricing input; or reframes only some while leaving a pitch in
Q1.

*(Clause corrected after run 1 on 2026-09-03. It previously read "keeps any of
them in the output", which would have failed a correct answer: the passing
output quotes each banned question in the left column of a was→now rewrite
table, which is the clearest way to show what was replaced. The test is whether
a banned form survives as a question to ask, not whether it is ever named.)*
