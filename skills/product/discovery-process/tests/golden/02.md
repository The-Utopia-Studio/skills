# Golden 02 — "Set up discovery" (routing: cycle vs standing practice)

## Input

A fellow. "We want to get better at discovery generally — right now we just
build whatever the loudest customer asks for. Set up discovery for us."

## Expected shape of a good output

This is the boundary the SKILL.md now names as the one that matters most, and
the correct answer routes away.

- Reads the tell: "generally", "get better at", no specific question and no
  deadline. The fellow wants a **standing practice**, not one bounded
  investigation.
- Routes to `continuous-discovery-engine` and says what it does: one living
  opportunity tree (outcome → opportunities → solutions → tests) fed by
  customer interviews, production traces and eval telemetry, kept current after
  launch.
- Draws the boundary explicitly: this skill is a cycle **with an end** — it
  answers one question and stops. That skill is a practice **with no end**. A
  fellow who runs this skill repeatedly to get a standing practice will do six
  disconnected investigations and no accumulation.
- Names the in-scope handoff so this does not read as a brush-off: the first
  real question that comes out of the opportunity tree is exactly what this
  skill is for. Set up the engine, then run a cycle against its top
  opportunity.
- Does not invent the fellow's outcome metric or opportunity tree.

## Auto-fail if

Opens Phase 1 and runs a cycle; proposes an opportunity tree itself (that is
`continuous-discovery-engine`'s artifact); invents the fellow's north-star
outcome; declines without naming the destination; or treats "loudest customer"
as the framed problem.
