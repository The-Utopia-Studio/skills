# Golden 03 — Durian Labs: guardrails for auto-tagging internal support tickets (MUNDANE)

## Input

Durian Labs' first workflow automates tagging inbound internal support tickets by team and
topic so they route to the right queue. Eval-first spec exists: one mode really matters,
**Miss-route** (wrong tag → ticket lands in the wrong queue), cost = a few minutes' delay
while someone re-routes it (Low `[Assumption]`); volume is high (hundreds/day). Autonomy L2
(auto-tags, a human can override). Fellow, cautious: "What guardrails do we need? Should a
person approve each tag before it applies?"

## Expected shape

- Bands the mode: Low cost × High volume → Q6. The correct guardrail is rules-in-code
  (schema: tag must be from the allowed set; a low-confidence tag routes to a default
  triage queue) + a confidence log + aggregate monitoring. Fail-open is acceptable here.
- Actively **removes** the proposed human sign-off. A per-ticket human approval on a Low-cost
  high-volume mode is waste — it cannot be afforded at hundreds/day, so it will be skipped,
  and the failure it guards costs minutes. Names this as the "remove the human where cost is
  low" side of the reframe.
- Sets a confidence threshold below which a ticket goes to the default triage queue rather
  than a guessed tag — cheap escalation, no person needed. τ derived against the acceptable
  miss-route rate, not felt.
- Adds a monitor: alert if the aggregate miss-route rate breaches the acceptable rate over a
  window — the guard for a high-volume mode is the *rate*, not per-item review.
- Does not manufacture a catastrophe to justify heavier guardrails. The honest answer is a
  light one. Tags the cost `[Assumption]`.
