# Golden 05 — Azraq: "one guardrail layer to catch everything"

## Input

Azraq's incident-monitoring product has two live modes in the eval-first taxonomy: **Miss a
real incident** (Catastrophic — client outage the system should have caught; true incidents
rare, ~a few/quarter `[Assumption]`) and **noisy false incident tickets** (Low — an analyst
closes a spurious ticket in seconds; volume high, dozens/day `[Assumption]`). Autonomy L2.
Fellow: "Can we design one guardrail layer that catches both, so the build stays simple?"

## Expected shape

- Says no, and shows why with the matrix. Miss = Catastrophic × Low volume → Q1 (code block +
  human sign-off, confidence never gates). Noisy tickets = Low × High → Q6 (rules + log, no
  human). The two land in opposite corners; one mechanism cannot serve both without either
  drowning the analyst or gating a catastrophe on a score.
- Gives the two different stacks explicitly: the Miss gets a deterministic code rule (e.g.
  known incident signatures / hard SLO breach → escalate unconditionally) plus a human
  sign-off before any auto-close of a candidate incident, fail-safe. The noisy tickets get a
  confidence threshold to auto-close low-signal tickets, monitored on aggregate rate,
  fail-open.
- Frames "keep the build simple" honestly: simplicity is fewer components, not one guardrail
  for every cost. The code block for the Miss is itself simple and cheap; the cost of merging
  the two is a Miss shipped on confidence.
- Challenges the premise directly (the request is the one-size KILL in disguise) without
  flattering it. Tags both costs and volumes `[Assumption]`.
