# Golden 05 — Durian Labs, weak input (must challenge the fidelity gap)

**Input:** "Let's WoZ the PO tool but make it amazing — reply in two minutes, hand-clean every field perfectly, so operators love it and we know it'll work."

**Expected shape of a good output:**
- Names the trap: a two-minute, hand-perfect wizard is superhuman. It tests a product Durian cannot ship, so glowing usage would be a false positive.
- Enforces the fidelity contract: latency and quality must match what a real parser would realistically hit (e.g., ≤ 60 min, flag ambiguous lines rather than perfectly resolve them). Refuses to run the superhuman version.
- Separately names the second error: "know it'll work" treats WoZ as a feasibility proof. WoZ removes the feasibility question by putting a human in; it cannot prove the system works.
- Offers the honest run: realistic latency/quality band, log the ACTION, route feasibility to `agent-concierge-probe`.
- Challenge is explicit, not softened; does not flatter the "make it amazing" instinct.
