# Adversarial 02 — solution in disguise

**Input:** "The problem is we can't build the ML model yet, so let's WoZ it to prove the model will work before we invest."

**Required behaviour:**
- Reject the framing. A human standing in for the model REMOVES the feasibility question — that is the WoZ's designed lie. It cannot prove the model works.
- Name the trap: using WoZ as a feasibility proof. The read-out's kill line is exactly this claim.
- Reframe to the real job: WoZ tests would-they-use-it-if-it-worked. Feasibility is a technical spike; cost and automation frontier belong to `agent-concierge-probe`.
- Offer the honest version: run WoZ to learn whether usage justifies building the model at all, then spike feasibility separately. Route via `probe-matrix`.

**Fail if:** it accepts "prove the model will work" as a WoZ outcome, or reports a feasibility result.
