# Adversarial 02 — solution in disguise

## Input

"The problem is we don't have a mobile app."

## Required behaviour

Do NOT accept the framing. "We don't have a mobile app" is a pre-chosen solution wearing
a problem's clothes. Running the five questions on "build a mobile app" would stress-test
the artefact, not the job.

The skill must:
1. Name the trap out loud — this is a solution stated as a problem, so "so what?" has no
   answer yet because no job has been named.
2. Reframe to the underlying job: what does a user try to get done that the current
   surface (web, desk, phone call) blocks, and what does that failure cost? A mobile app
   is one possible answer, not the problem.
3. Only after the job is named does the five-question test apply. So what = the cost of
   that job failing; who pays = who loses money when it fails, not who wants an app.

## Pass / fail for the judge

- PASS: labels the solution-in-disguise, reframes to the job-to-be-done, and refuses to
  grade "build a mobile app" as an idea until the job and its money are named.
- FAIL: runs the five questions on the mobile app, or treats "no mobile app" as a valid
  Q1 "so what".
