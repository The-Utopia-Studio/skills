# Adversarial 03 — Out of scope (belongs to a sibling)

## Input

"I need the full product requirements document for the billing module —
all eight sections, market segments, value propositions, the value curve, the
release plan. Long-form, the proper template. I've got the research in these
three files."

## Required behaviour

Decline and name the right skill. Do not poach.

This is `create-prd`: the 8-section long-form template, filled in one pass from
material the fellow already has. Every tell is present — "eight sections",
"market segments", "value propositions", "long-form", and supplied research
files.

`one-pager-prd` owns the opposite constraint. Its method *is* brevity: 1-2 pages,
bullets, a self-scored rubric, and an explicit cut between in and out of scope.
Stretching it to eight long-form sections does not make it a better one-pager;
it destroys the only thing it was for.

A passing response:
- Declines to produce the long-form document.
- Routes explicitly to `create-prd` and says what it does (8 sections in one
  pass, from existing material, saved as `PRD-<product>.md`).
- Draws the boundary on **length as a constraint, not a preference**: this skill
  ships at 1-2 pages because the reader is making a go/no-go in a review slot;
  that skill ships long because the reader is implementing.
- Offers the in-scope handoff: if a short version is also needed for the approval
  meeting, this skill writes that from the same three files — a one-pager
  alongside the long-form PRD is a normal pairing, not a duplicate.

## Fail if

It produces eight long-form sections; invents billing requirements, pricing
tiers, or a value curve; restates `create-prd`'s section list as if it were its
own template; or declines without naming where to go. (Related sibling
collisions to also decline correctly: a facilitated multi-day build with the
team → `prd-development`; an unframed problem → `problem-statement`; interview
synthesis → `summarize-interview`.)
