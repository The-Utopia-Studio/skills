# Golden 04 — Trivially small feature (mundane; does a one-pager earn its keep?)

## Input

A fellow. "One-pager for changing the 'Save' button label to 'Save changes'. My
manager wants a spec for every change now."

## Expected shape of a good output

The mundane case tests whether the skill will say the artifact is not worth its
own cost.

- Names it honestly: a copy change on one button does not need a one-pager. The
  skill's own key insight — *"brevity forces clarity; if you can't explain it in
  1-2 pages you haven't thought it through"* — cuts the other way here. This
  can be explained in one sentence, so a page adds nothing but ceremony.
- Recommends the smallest honest artifact: a ticket with the before/after label
  and the reason. Two lines.
- Does **not** inflate it — no invented confusion metrics, no "reduce
  mis-clicks by 12%", no personas for people who press Save.
- Handles the real constraint gracefully: the manager wants a spec for every
  change. That is a process question, not a product one. Offers the one-liner
  format that satisfies it without pretending the change carries a problem
  statement and a metric tree.
- If the fellow insists, produces the shortest possible honest version — problem
  (label is ambiguous about what is saved), change, and "no metric: this is a
  clarity fix, not a measurable one" stated plainly rather than faked.

## Auto-fail if

Produces a full one-pager with invented metrics, personas, and scope sections
for a button label; claims a measurable impact it cannot have; flatters the
request as good practice; or refuses without offering the two-line alternative
that actually solves the fellow's problem with their manager.
