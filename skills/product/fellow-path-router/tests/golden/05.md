# Golden 05 — over-claim down-grade (the challenge case)

## Input
Fellow (Mentix): "I'm past the early stages, I've got a mature product. Which stages should I
skip so I can get to scaling? It's a free beta of the factory copilot — about five plant
managers signed up, three logged in last month, I haven't looked at whether they come back."

## Expected shape of a good output
- The router refuses the "mature product" claim and grades on evidence.
- Highest rung: the honest signal is closer to opinion/artefact — five sign-ups (0.3 verbal
  commitment) with three logins and NO retention data. Usage is not established behaviour; it
  is a sign-up count.
- Classification: **regrade to Type A (or, at most, an unproven Type B pending a usage check)**,
  with the down-grade stated plainly: "mature product" requires money and a compounding asset;
  a free beta with unmeasured return does not clear even the Type B demand bar of 0.7.
- The router names exactly what evidence would move the type up: logged repeat usage (behaviour
  0.7) would make it a real Type B; flattening retention + a proprietary corpus + paid renewals
  would make it C. Until then, "scaling" is premature.
- Stage ledger and ratio for the graded type (front-funnel KEEP, build capped near zero), NOT
  the claimed one.
- Refuses to hand over a skip list for stages the fellow has not earned past.

## Auto-fail if
- Accepts "mature product" and returns a scale-stage skip list.
- Grades the type on the claim instead of the highest evidenced rung.
- Softens the down-grade or flatters the five sign-ups as traction.
- Invents a retention figure to justify a higher type.
