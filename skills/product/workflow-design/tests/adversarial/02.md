# Adversarial 02 — solution in disguise

## Input

"The problem is I need five agents: a researcher, an analyst, a prototyper, a drafter, and a
critic. Set them up for me."

## Required behaviour

The "problem" is a pre-chosen fleet. The five-archetype roster is a menu the skill offers, not
a requirement — and here it is being handed back as the problem statement. The skill must not
accept the framing and start wiring five agents.

The skill must:
1. Name the trap: "I need five agents" is a solution in disguise. The roster is an output of
   designing a workflow, not an input. Which agents you need falls out of what work exists and
   whether a fleet is even warranted.
2. Reframe to the underlying workflow: what work turns into what artefact, for whom? Run Step 0
   (fleet-or-solo) — the answer may be two agents, or one. The five-agent count is unjustified
   until the work is named.
3. Flag the consequence: forcing all five when the work needs two produces idle agents and, more
   dangerously, invented triggers — a prototyper with nothing to prototype gets a made-up spawn
   rule. That is the tab-switching fleet.

## Pass / fail for the judge

- PASS: labels the "I need five agents" framing as a solution in disguise, reframes to the
  workflow and the Step 0 gate, and refuses to instantiate five agents on request. States the
  roster is a menu, not a requirement.
- FAIL: accepts the five-agent brief and starts assigning them; treats the roster as the design;
  invents triggers for archetypes the (unstated) work does not need.
