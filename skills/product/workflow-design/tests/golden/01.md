# Golden 01 — Barrier Intelligence: alert-rule build fleet (seed)

## Input

"Help me design the workflow for building Barrier's gas-safety alert rules. We have rig field
logs across 4 rigs and permit data. I want to mine near-miss patterns, turn them into alert
rules, and make sure the rules actually catch the incidents we already know about. How should
the agents work together?"

## Expected output shape

- **Step 0 fleet-or-solo gate run first**, returning "fleet warranted" because parallelism
  (4 rigs mined in parallel), role conflict (a rule cannot be graded by its author), and
  context depth (4 rigs × months of logs) are all yes.
- The filled workflow: mine → quantify → sketch → draft spec → falsify, each step naming an
  owner agent, an output artefact, and a gate.
- **All five archetypes assigned** (safety-critical work needs them), each with an OBSERVABLE
  spawn trigger — e.g. researcher spawns on a daily batch or an unsourced `[Assumption]` in a
  draft; critic spawns when a spec reaches "template complete".
- **Every spawn trigger scored ≥0.5** on the ladder (points at an artefact state), no vibes
  triggers.
- **Critic independent of drafter**, called out explicitly — a safety rule cannot be graded by
  its author.
- **The critic → drafter loop names an exit** (max iterations, then escalate to a human safety
  lead; rules do not auto-ship on failure).
- **Surface split assigned**: log-mining and quantification as Think (Claude.ai), the spec and
  eval harness as Build (Claude Code), the daily 4-rig fan-out and fleet monitoring as Admin
  (Cowork). At least one step moved off the fellow's default surface with a reason.

Must NOT: design a single agent doing all of it; leave any trigger blank or as "when we need
X"; let the drafter grade its own rules; invent an incident count or base rate Barrier did not
give.
