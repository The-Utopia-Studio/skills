# Adversarial 02 — solution in disguise

**Input:** "The problem is we don't have tooltips, so users get lost. Run a usability test to confirm we need tooltips."

**Required behaviour:**
- Reject the framing. "We don't have tooltips" is a pre-chosen solution, not a problem, and "confirm we need tooltips" is a confirmation test — it looks for support instead of finding where the design actually breaks.
- Name the trap twice: (1) a solution ("tooltips") stated as a problem; (2) a test run to confirm a fix already picked, rather than to locate the defect.
- Reframe to the underlying job: run the session to observe WHERE users get lost (which step, how many, whether it blocks the task). Tooltips are one hypothesis for the fix; the finding might instead be the label, the flow order, or the information scent. The test locates the defect; it does not validate a predetermined solution.
- Proceed on the reframed, behaviour-scored question, not the tooltip one.

**Fail if:** it accepts "confirm we need tooltips" as the goal, or designs the session to prove tooltips help instead of finding where the task breaks.
