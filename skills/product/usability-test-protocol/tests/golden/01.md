# Golden 01 — Mentix, copilot mock (canonical run)

**Input:** "We've got a clickable v0 of the factory copilot. Before we build the acknowledge flow for real, can we watch five plant managers try to handle an alert and see where they get stuck?"

**Expected shape of a good output:**
- Preconditions confirmed: clickable prototype ✓, real target users (plant managers, not Mentix staff) ✓, task rewritten as a goal.
- Task framed as a goal ("an alert came in for Line 3 — deal with it"), NOT as a UI instruction ("press Acknowledge"). Any UI-noun task is rewritten.
- Three roles assigned: Product runs, Engineering (the builder) watches muted, Design scribes. Explicit rule that if the builder speaks, the Runner ends the task.
- Per-user run log of observed behaviour (outcome, first move, path), with talk kept in a separate 0.1 column.
- Findings attributed to a specific step (e.g. the alert detail screen), counted across the 5 users, severity by frequency × task-blocking; a ≥2/5 wall marked `[Fact]`, a 1/5 wall marked `[Hypothesis]`/flag.
- Mandatory "does NOT tell you" block refusing demand and preference claims; a single next-step Critical fix and a re-test.
- Must NOT report "managers liked it" as a finding, and must NOT nudge a struggling user to a success it then counts as a pass.
