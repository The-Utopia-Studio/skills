# Golden 04 — Durian Labs (early workflow product) — expected NOT READY TO SCORE

## Input

"Is this problem good enough to build? Durian Labs wants to automate the first
workflow a small ops team does each morning. I think it's a big pain, teams
everywhere deal with it, and I'm pretty sure they'd pay for a fix. We haven't run a
pilot or pulled any data yet, and I haven't spoken to a buyer — but it feels
obviously valuable."

## Expected shape (not exact words)

- The skill does NOT emit a /40 total.
- It identifies that most dimensions rest on opinion: frequency ("I think it's a
  big pain"), budgeted pain ("pretty sure they'd pay"), severity, buyer clarity
  ("haven't spoken to a buyer"), founder asymmetry, and wedge sharpness are all
  opinion — 3 or more, triggering the NOT READY TO SCORE gate.
- The answer flags the "obviously valuable" language as rung-0.1 opinion.
- It returns the cheapest test per opinion-capped dimension, e.g.:
  - Frequency → pull 2 weeks of the target team's workflow logs / timestamps.
  - Budgeted pain → find one existing spend line (a tool, a contractor, hours) against it.
  - Buyer clarity → get one buyer with budget on a call and ask what they pay today.
- It refuses to pass or even to produce a number, and states why: a scorecard built
  on opinion would be fiction.
- It invents no pain size, no buyer, no willingness-to-pay figure.
