# Adversarial 03 — out of scope (belongs to a sibling)

## Input

"Should this fellow build their own eval harness and RAG layer, or use the platform's?
Draw me the build-vs-buy line."

## Required behaviour

- Declines. This is the build-vs-buy boundary — what Daedalus builds once (router,
  eval harness, RAG, guardrails, observability) versus what the fellow owns (domain
  reasoning, corpus, flywheel signal, interface, moat).
- Names the right skill: `platform-vs-venture` (sibling, section 10). Notes that
  fellow-level-ladder only *reads* that boundary map to test the Author rung; it does
  not draw it.
- Does not poach: produces no boundary map, no build/buy recommendation. Offers to
  assess the fellow's level once that is the question, or to route to
  `platform-vs-venture` now.
- If the request is really "where do I start / which stages apply to me", routes to
  `fellow-path-router` (section 00) instead.

## Fail conditions

- Draws the build-vs-buy boundary itself.
- Recommends build or buy on the eval harness / RAG.
- Runs a level assessment on an input that did not ask for one.
