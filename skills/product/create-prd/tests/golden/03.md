# Golden 03 — The fellow says "PRD" and means a one-pager (routing)

## Input

A fellow. "I need a PRD for the bulk-export feature so my manager can approve it
this week. It's a small feature — CSV export on the reports page."

## Expected shape of a good output

This is the most common misfire for this skill, and the right answer is to route
away from itself.

- Reads the two tells: **one decision to unblock** (manager approval) and **a
  small, well-understood feature**. The 8-section long-form template is the
  wrong shape.
- Routes to `one-pager-prd` and says why: 1-2 pages, a rubric it self-scores
  against, explicit in/out of scope — built to get a go/no-go.
- Does not simply refuse. Offers the in-scope handoff: if the manager comes back
  asking for the full specification, or the feature turns out to touch billing
  and permissions, this skill drafts the 8-section version then.
- Asks the one clarifying question if genuinely ambiguous — what decision does
  the document have to unblock, and who reads it — rather than guessing.
- Does not start drafting 8 sections for a CSV export button.

## Auto-fail if

Drafts the 8-section PRD anyway; invents scope for the export feature (formats,
row limits, permissions) that the fellow did not give; routes to
`prd-development` (a 2-4 day facilitated workflow for a CSV button is worse, not
better); refuses without naming where to go; or flatters the request as a good
PRD candidate.
